CO2 - Q7: DIAGNOSE, REDESIGN AND VALIDATE
Selected program: Q6 - Counting ways to climb temple steps

A. DIAGNOSE THE BOTTLENECK
The original recursive function calls itself twice for most values of n.
It recalculates the same smaller stair counts many times.
The number of function calls grows exponentially as n increases.

B. DESIGN OBJECTIVE
Calculate the same answer in O(n) time and O(1) extra space.

C. REVISED DESIGN
Keep only the previous two answers and calculate the next answer in a loop.
This avoids repeated recursive calls and does not need a cache.
Trade-off: the iterative version is less direct than the recursive definition.

Pseudocode:
1. Set previous = 1 and current = 1.
2. Repeat from step 2 to n.
3. Calculate next = previous + current.
4. Move current into previous and next into current.
5. Return current.

D. PREDICTION
The iterative version should use n-1 loop iterations and O(1) extra space.
It should be much faster than plain recursion for larger n.

E. IMPLEMENTATION AND VALIDATION

F. FINAL EVALUATION
The redesign meets the objective: it calculates the same result using O(n) time
and O(1) extra space, without recursive calls or a cache.
Plain recursion is useful for demonstrating the mathematical definition and
small inputs, but the iterative version is more suitable for large staircases.

Complexity comparison:
Plain recursion: O(2^n) time and O(n) call-stack space.
Iterative redesign: O(n) time and O(1) extra space.
