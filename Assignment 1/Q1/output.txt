Observation: for all eight households the two designs return the same single
outcome. The if–elif–else form guarantees exactly one result even when future
requirements cause two branches to overlap, whereas each separate if would start
adding outcomes independently (producing duplicates / multiple subsidies).

Preliminary: branch orderisation cost is negligible for few slabs, but matters when
requirements grow into many tiers. match–case would scale linearly with k:
  per-decision O(k) (each case checked until a guard matches).

Decision kept: combine the band condition with a Boolean `and`; nest an if only
when a sub-policy inside a tier is itself conditional. This stays readable and easy to
extend, and the elif chain remains the single-decision backbone.
